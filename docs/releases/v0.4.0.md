Stemma 0.4.0 brings required signatures for central environments, selective signing, read-back reviews, share branches with interactive commands, citations and site improvements, more agent harnesses, and a faster CI.

## What upgrading means for a library

- **Some signatures go stale with no change.** Prose now exports lists, so signatures of environments whose prose has lists become stale and need signing again. The fingerprint version is intentionally unchanged.
- **Unsigned central environments now block.** `[policy] require_signed_central` is on by default, and `stemma upgrade` writes it. Central environments already on `main` without a signature must be signed before the next pull request; `stemma status` lists them.
- **Free-text `cited` marks fail** until their key is in `references.bib`, which `stemma upgrade` creates if it is missing.
- **`stemma check --json`:** `build` is now always an object (`{"ok": …}`), and there is a new `hints` field.
- **The workflow has two required checks,** `Stemma verify` and `Stemma check`. Repository setup, run by `init` and `upgrade` through `gh`, sets them and allows merge commits only.
- **`AGENTS.md`:** the guard block changed, so `stemma check` fails until `stemma upgrade` runs.
- **Sharing goes through `share/<branch>`.** Pull requests already open from `work/<person>` finish as before.

## New

- `stemma key add`
- `stemma remote` (a personal remote for working branches)
- `stemma agent <harness>`: Claude Code, Codex, DeepSeek and OpenCode
- Selective signing
- The branch picker, and interactive `share` and `upgrade` (`--yes` skips the questions)
- Read-back review marks and notes, and a navigable read-back page
- Citations, a bibliography page, visible labels, and central marks with their signature state on the site
- Source plans (`sources/`) with the `stemma-sources` skill
- `[site] publish` for GitHub Pages
